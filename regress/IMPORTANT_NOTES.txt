Python 3 port (#36)
-------------------
regress.py now runs on Python 3 with only the standard library plus
python3-dpkt (raw IP socket to send, AF_PACKET on lo to capture,
`ip route` for the test networks); dnet_compat.py stands in for the old
libdnet bindings. Run with `sudo make -C regress test`.

Deterministic suite, CI gate (#74)
----------------------------------
The suite now runs over a veth pair (hdt0 = honeyd, hdt1 = harness)
instead of lo, so every probe and reply is seen exactly once; see the
comment at the top of regress.py for the wiring. It needs root and
NET_ADMIN (veth, routes) but no network namespace.

honeyd -R <n> seeds both its libdnet RNG and libc rand(); with that, the
sequence of random draws (IP IDs, ISNs, TCP timestamps, MACs, drops) is
identical run to run. What the harness still normalises:
  * TCP timestamp option values are printed as "TS" (wall clock);
  * checksums of honeyd's replies are printed as ok/BAD rather than the
    value (they cover the timestamps);
  * with configs that make honeyd send through a raw IP socket (no
    routing topology, no template MACs: config.1), Linux replaces an IP
    ID of 0 with a random one unless DF is set, so those reply IDs are
    printed as "<kernel>". config.2 (routing) writes frames itself and
    its IDs are compared exactly.

The *.output.* files were regenerated under Python 3 and were identical
over 5 consecutive runs. All tests in general.py, detect.py and
routing.py gate CI (sanitizer job). Regenerate with `make generate` and
review the diff when honeyd's behaviour changes on purpose.

nmap.py is not ported: it needs an nmap.prints file that is no longer in
the tree and BSD's lo0, and is no longer part of `make test`.
