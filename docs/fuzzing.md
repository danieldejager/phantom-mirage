# Fuzzing honeyd

honeyd ships three [libFuzzer](https://llvm.org/docs/LibFuzzer.html)
harnesses under `fuzz/`, built with clang and
`-fsanitize=fuzzer,address,undefined`.

| Target          | Entry point                         | Seeds                   |
|-----------------|-------------------------------------|-------------------------|
| `fuzz_packet`   | `honeyd_recv_cb()`: one Ethernet frame as delivered by pcap (ARP, IPv4, TCP, UDP, ICMP, fragments, GRE, routed hops) | `fuzz/corpus/packet`    |
| `fuzz_config`   | `parse_line()`: config text (the same path as the control socket and `-f`), then a SIGHUP-style reset | `fuzz/corpus/config`    |
| `fuzz_macprefix`| `ethernetcode_init()` on an `nmap-mac-prefixes` file, plus lookups | `fuzz/corpus/macprefix` |

`fuzz_packet` and `fuzz_config` run honeyd's normal start-up first. This
loads the real `nmap-os-db`, `xprobe2.conf`, `nmap.assoc`, `pf.os` and
`nmap-mac-prefixes` from the source tree. `fuzz_packet` then installs a
fixed config (`fuzz/corpus/config/packet_harness.conf`: Linux and Windows
templates on 10.0.0.2, 10.0.0.3 and 10.1.0.2 behind a router) on a fake
Ethernet interface `fuzz0` (10.0.0.1/24, MAC 02:00:00:00:00:01).

Nothing leaves the process. The link step wraps `fork`, `execv`,
`execvp`, `connect` (non-`AF_UNIX`), `ip_open`, `ip_send` and `eth_send`
with stubs (see `fuzz/fuzz_common.c`), so replies are built in full and
then dropped.

## Build and run

```sh
sudo apt-get install clang libclang-rt-dev   # plus the normal build deps
fuzz/build.sh                                # binaries land in fuzz/out/

export ASAN_OPTIONS=detect_leaks=0
mkdir -p /tmp/corp && cp fuzz/corpus/packet/* /tmp/corp/
fuzz/out/fuzz_packet -max_len=4096 /tmp/corp           # fuzz
fuzz/out/fuzz_packet -runs=0 fuzz/corpus/packet        # replay the seeds
fuzz/out/fuzz_packet crash-<sha1>                      # reproduce
fuzz/out/fuzz_packet -minimize_crash=1 -runs=10000 crash-<sha1>
```

`build.sh` configures the tree with `CC=clang` and the sanitizer flags
when there is no `Makefile`. If you have built with gcc before, run
`make distclean` first. Packet seeds are generated by
`fuzz/make_seeds.py`.

Notes:

* Leak detection is off. honeyd keeps its tables for the life of the
  process, so LSan reports are noise.
* UBSan `alignment` is disabled. honeyd reads headers from pcap buffers
  that are not 4-byte aligned, which is fine on x86 and arm64.
* `-fno-sanitize-recover=all` makes every UBSan report fatal.
  `UBSAN_OPTIONS` is unreliable here, because honeyd drops privileges
  and the runtime can then no longer read `/proc/self/environ`.
* Use `-fork=N -ignore_crashes=1` for long runs, so that one known
  finding does not stop the campaign.

## CI

The `fuzz` job in `.github/workflows/build.yml` builds the targets and
then:

1. **Replays every seed (gate).** The seeds include a regression input
   for each fixed bug (`regress_*`, `routes`), so any regression fails
   the build.
2. **Fuzzes each target for 60 s (informational).** Open findings below
   can still turn up, so crashes are listed in the job summary and
   uploaded as the `fuzz-artifacts` artifact, but do not fail the build.

| #63 | config | `router_end()` leaves `reverse`/`entry_routers` dangling; the second config load (SIGHUP) uses freed nodes → double free | fixed |
| #59 | packet | ICMP echo reply payload length ignores IP options → heap over-read, leaked bytes echoed to the sender | fixed |
| #60 | packet | `tcp_recv_cb`/`tcp_do_options` trust `th_off` and `opt_len` (read before the length check, past the segment) | fixed |
| #61 | packet | `pf_osfp_fingerprint_hdr` walks `th_off*4` option bytes that may be beyond the captured packet | fixed |
| #62 | packet | `honeyd_recv_cb` reads the Ethernet source before checking `caplen >= 14` | fixed |
| #65 | packet | `personality.c` ISN generator converts a negative or > 2^32 `double` to `uint32_t` | fixed |
| #66 | config | `parse.y`: an illegal IP address yields an unset `ipaddr`, so `addr_ntoa()` returns NULL into `strcmp`/`strdup` (`templ_compare`, `template_create`) | open (needs `parse.c` regenerated) |

Reproducers for open findings live in `fuzz/crashes/open/` (named
`<target>-<issue>-*`). CI does not replay them. Once a finding is fixed,
move its file into `fuzz/corpus/<target>/` so it becomes a regression
test.
