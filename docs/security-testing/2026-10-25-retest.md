# Retest of v1.7.0-6 (decoys only)

Date: 2026-10-25. Tester: Claire. Attacker host: Windows VM, nmap 7.992, TCP connect scans (no admin rights).
Target build: v1.7.0-6 (commit `613dabf`), clean install on the Ubuntu lab VM.

## Scope

Decoys only, as set by the owner on 2026-10-25: `192.168.1.240` to `.247` and `.250`. The sensor (`.112`), the router and every other device were not probed.

Deviation from the agreed scope: the build was installed with `-n 192.168.1.0/24`, so the decoy range is the whole /24, not `192.168.1.240/29`. Risk to check later: the sensor may answer for addresses of real devices. Not tested here, because probing other addresses is out of scope.

## Results

| ID | Test | Result |
|----|------|--------|
| R1 | TCP on all 9 decoys, top 100 ports | Pass. 21, 22, 23, 80, 443, 445, 3389 open on every decoy, the other 93 ports refuse immediately. Closes #123. |
| R2 | Service banners on `.240` and `.250` | Finding (Low, below). All 7 open ports accept the connection but return no recognisable banner. |
| R3 | Full port range (1-65535) on `.240` | Pass. Only the same 7 ports are open. |

## Commands

```
nmap -sT -Pn -n -T3 --top-ports 100 --reason -oN C:\pentest\R1-decoys-tcp.nmap 192.168.1.240-247 192.168.1.250
nmap -sT -Pn -n -sV --version-light -p 21,22,23,80,443,445,3389 -oN C:\pentest\R2-banners.nmap 192.168.1.240 192.168.1.250
nmap -sT -Pn -n -p 1-65535 --min-rate 300 -oN C:\pentest\R3-fullports-240.nmap 192.168.1.240
```

## Finding

**Low: open decoy ports return no banner.** Real FTP, SSH, telnet, HTTP and RDP services announce themselves or answer a probe. These ports accept the connection and say nothing, and nmap labels every one with a question mark. An attacker can tell a decoy from a host by this alone. Recommendation: have the decoys return a plausible banner per port, or document that the decoys are detection tripwires and not lures. Not yet filed as an issue.
